# 병렬 작업: 터미널 멀티 세션 vs 데스크톱 앱 멀티 세션 vs 멀티 에이전트

> 관련 모듈: 3, 11 (7, 15, 19와 연결)
> 기준: 공식 문서 [Desktop](https://code.claude.com/docs/en/desktop), [Agent view](https://code.claude.com/docs/en/agent-view) (2026년 10월 확인). 일부 기능은 연구 미리보기(research preview)라 바뀔 수 있습니다.

---

## 1. 먼저 구분할 것: "멀티 세션"과 "멀티 에이전트"

| 구분 | 무엇인가 | 누가 나누나 | 예시 |
|---|---|---|---|
| **멀티 세션** | 서로 독립된 대화(작업)를 여러 개 동시에 진행 | **사람**이 작업을 나눠 각 세션에 맡김 | 세션 1: 수강 취소 기능, 세션 2: N+1 수정 |
| **멀티 에이전트** | 한 작업 안에서 Claude가 **서브에이전트**에게 일을 나눠 맡김 | **Claude**가 판단해서 위임 | 구현 후 리뷰어 3명을 병렬 실행 |

> 💡 **오해하기 쉬운 점:** 데스크톱 앱을 쓴다고 해서 자동으로 멀티 에이전트가 되는 것은 아닙니다. 서브에이전트 위임은 **터미널, IDE, 데스크톱, 클라우드 어디서나** 같은 방식으로 일어납니다. 데스크톱 앱은 여러 세션과 서브에이전트를 **화면에서 보고 관리하기 쉽게** 해 줍니다.

---

## 2. 병렬 작업 방식 5가지

### 방식 A. 터미널 도구로 직접 여러 세션 운영

```bash
# 워크트리를 만들고 터미널 창·분할 화면마다 claude 실행
claude -w cancel-enrollment      # 격리된 worktree에서 세션 1
claude -w fix-n-plus-one         # 다른 창에서 세션 2
# 또는 git worktree add 후 각 폴더에서 claude
```

- 도구: Windows Terminal 분할 화면, tmux, wmux ([터미널 도구](./14-environments-and-terminals.md))
- 사람이 창을 오가며 각 세션을 확인하고 응답

### 방식 B. CLI 백그라운드 세션 + 에이전트 뷰

```bash
claude --bg "enrollment 도메인 단위 테스트 보강"    # 백그라운드로 시작
claude --bg "MFE shared 의존성 버전 정리"
claude agents                                   # 모든 세션을 한 화면에서 관리
```

- 터미널을 닫아도 세션이 계속 실행됨 (별도 관리 프로세스가 유지)
- 백그라운드 세션은 수정 전에 **자동으로 자기 워크트리**(`.claude/worktrees/`)로 이동해 서로 충돌하지 않음
- 에이전트 뷰에서 상태(작업 중, 입력 필요, 완료)별로 모아 보고, `Space`로 미리 보기, 바로 답장
- 연구 미리보기 기능이라 화면과 동작이 바뀔 수 있음

### 방식 C. 데스크톱 앱 멀티 세션

- 사이드바에서 **+ New session** (`Ctrl + N`), `Ctrl + Tab`으로 세션 전환
- Git 저장소에서는 세션마다 **워크트리 격리** 옵션 → 세션별 독립 작업 공간
- 시각적 diff 검토와 줄 단위 코멘트, 앱 미리보기(Browser 패널), PR·CI 상태 확인
- 세션 하나에서 Claude에게 다른 세션의 진행 상황을 확인하게 할 수 있고, 범위 밖 작업을 발견하면 **새 세션으로 분리하자고 제안**(task chip)
- 서브에이전트 패널에서 위임된 작업 확인·중지
- PR 머지 후 세션 자동 정리(auto-archive) 설정 가능

### 방식 D. 한 세션 안의 멀티 에이전트 (서브에이전트)

```text
수강 취소 기능을 구현하고, jpa-reviewer와 mfe-integration-checker로 병렬 검토해줘.
```

```text
/batch 모든 컨트롤러의 OpenAPI 어노테이션을 사내 규칙에 맞게 보완해줘
```

- Claude가 작업을 나눠 서브에이전트에게 맡기고 결과를 모아 통합 ([에이전트 가이드](./10-agents.md))
- `/batch`: 대규모 변경을 독립 단위로 나누고, 계획 승인 후 백그라운드 서브에이전트들이 병렬로 처리
- `/simplify`, `/code-review` 같은 번들 스킬도 내부적으로 여러 에이전트를 병렬 실행

### 방식 E. 클라우드 세션

- 웹, 데스크톱(Cloud 선택), `claude --cloud "작업"`으로 시작
- 내 컴퓨터를 꺼도 진행, 결과는 브랜치·PR로 받음
- 로컬 DB·사내망 접근 불가

## 3. 비교: 터미널 멀티 세션 vs 데스크톱 멀티 세션

| 기준 | A. 터미널 도구 (직접 운영) | B. CLI 에이전트 뷰 | C. 데스크톱 앱 |
|---|---|---|---|
| **준비** | 워크트리·창을 직접 구성 | `--bg`, `claude agents` | 버튼으로 새 세션 |
| **작업 공간 격리** | 직접 워크트리 생성 (`-w`로 간편화) | 자동 워크트리 | 자동 워크트리 (옵션) |
| **상태 파악** | 창을 하나씩 확인 | 상태별 목록, 미리 보기 | 사이드바, 세션 간 확인 요청 |
| **변경 검토** | 텍스트 diff (`/diff`, `git diff`) | 텍스트 diff | **시각적 diff + 줄 코멘트** |
| **앱 동작 확인** | 직접 서버 실행·브라우저 확인 | 직접 | **Browser 패널 미리보기** |
| **터미널 닫으면** | 세션 종료 (tmux·wmux는 유지) | 계속 실행 | 앱 실행 중 유지 |
| **원격 서버(SSH)** | ◎ | ○ | SSH 세션 지원 |
| **자동화·스크립트** | ◎ | ◎ (`--json` 출력) | △ |
| **학습 난이도** | 높음 | 중간 | 낮음 |
| **세밀한 제어** | ◎ | ○ | ○ |

### 어느 쪽이 유리한가

| 상황 | 유리한 방식 | 이유 |
|---|---|---|
| 입문자, 터미널이 낯선 팀원 | **C. 데스크톱** | 설치만 하면 세션·워크트리·diff가 화면으로 정리됨 |
| 화면 변경이 많은 프론트엔드(MUI, MFE) 작업 | **C. 데스크톱** | 미리보기와 시각적 diff로 확인이 빠름 |
| 서로 독립된 작업 3~5개를 동시에 | **B 또는 C** | 자동 워크트리 격리, 상태 한눈에 보기 |
| 서버(SSH)·리눅스 환경에서 작업 | **A (tmux) 또는 B** | 데스크톱 없이도 세션 유지 |
| 스크립트로 작업을 대량 배분·감시 | **B. CLI 에이전트 뷰** | `claude --bg`, `claude agents --json`으로 자동화 |
| 한 기능을 설계·구현·검토로 나눠 진행 | **D. 멀티 에이전트** | 맥락을 메인이 유지하며 역할 분담 |
| 같은 패턴의 대규모 반복 변경 | **D. `/batch`** | 자동 분할과 병렬 처리 |
| 몇 시간 걸리는 작업, 퇴근 후에도 진행 | **E. 클라우드** | 내 컴퓨터와 무관하게 진행 |

### 결론

- **"어느 것이 더 좋다"보다 "작업과 사람에 맞게"**가 정답입니다
- **일반적인 추천:** 평소 개발은 **데스크톱 앱**(또는 IDE)으로 시작 → 익숙해지면 자동화·서버 작업에 **CLI(에이전트 뷰, tmux)**를 추가
- **한 작업 안의 분업**은 환경과 관계없이 **서브에이전트(멀티 에이전트)**로
- 혼합 예: 데스크톱에서 기능 개발 세션 2개 + CLI `--bg`로 테스트 보강 + 클라우드로 의존성 업그레이드

## 4. 병렬 작업의 공통 주의 사항

| 주의 | 설명 | 대책 |
|---|---|---|
| **사용량이 빨리 소진됨** | 세션·에이전트 수만큼 토큰을 사용 | 병렬 수를 정해 두고 `/usage`로 확인 ([토큰 최적화](./08-token-optimization.md)) |
| **리뷰가 병목** | 결과가 쏟아져도 사람이 검토할 수 있는 양은 한정 | **병렬 수 = 내가 리뷰할 수 있는 양**. 보통 2~4개로 시작 |
| **머지 충돌** | 같은 파일을 여러 세션이 수정 | 작업을 영역(디렉터리)별로 나누기, 공통 파일 변경은 순서대로 |
| **워크트리 정리** | 끝난 워크트리가 쌓임 | 커밋·푸시 후 정리, 자동 정리 기능 활용. 커밋하지 않은 변경은 삭제 시 사라질 수 있음 |
| **환경 차이** | 워크트리에는 `.env` 같은 Git 제외 파일이 없음 | 필요한 파일 복사 설정(`.worktreeinclude`) 확인 |
| **로컬 자원 충돌** | 여러 세션이 같은 포트로 서버 실행 | 세션마다 포트 분리, DB 스키마 분리 |

## 5. 실습

1. 같은 두 작업("수강 취소 API", "과정 목록 N+1 수정")을
   - A. tmux 또는 Windows Terminal 분할 + `claude -w`
   - C. 데스크톱 앱의 세션 2개 (워크트리 격리)
   로 각각 진행하고 준비 시간, 상태 파악, 검토 편의성 비교
2. `claude --bg`로 작업 2개를 맡기고 `claude agents`에서 상태 확인, 미리 보기로 답장
3. 한 세션에서 서브에이전트 리뷰어 3개를 병렬 실행하고, 데스크톱 앱의 서브에이전트 패널에서 진행 상황 확인
4. 팀 토론: 우리 팀의 기본 병렬 작업 방식과 동시에 돌릴 최대 세션 수 정하기
