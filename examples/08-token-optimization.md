# 예제: 토큰 사용량 최적화

> 관련 모듈: 19 (1, 8, 10, 11, 13과 연결)
> 예제 프로젝트: [EduHub](./00-sample-project.md)

---

## 1. 토큰은 어디에 쓰이는가

에이전트는 매 턴마다 **지금까지의 컨텍스트 전체**를 모델에 보내고, 모델이 응답을 생성합니다.

```
[컨텍스트 = 입력 토큰]
├── 시스템 지침 + 도구 정의 (기본 도구, MCP 서버 도구)
├── CLAUDE.md (모든 계층)
├── 스킬 목록 (이름과 설명만)
├── 대화 기록 (내 지시 + Claude의 응답)
└── 도구 결과 (읽은 파일, 명령 출력, 검색 결과)   ← 보통 가장 큰 비중
[응답 = 출력 토큰]
└── 설명, 생성한 코드
```

**핵심 이해**
- 대화가 길어질수록 매 턴의 입력이 커진다 → 같은 지시라도 **세션 후반이 더 비싸다**
- 컨텍스트가 가득 차면 자동 압축(compact)이 일어나고, 세부 내용이 요약되며 사라질 수 있다
- 앞부분이 같은 컨텍스트는 **프롬프트 캐싱**으로 비용이 줄어든다
- 토큰을 아끼는 것은 비용뿐 아니라 **품질**에도 좋다. 관련 없는 내용이 많으면 중요한 지시가 묻힌다

## 2. 측정하기

| 방법 | 용도 |
|---|---|
| `/context` | 현재 컨텍스트를 무엇이 얼마나 차지하는지 확인 |
| `/cost` (API 사용자) | 세션의 토큰 사용량과 비용 확인 |
| `--output-format json` (헤드리스) | 실행 결과의 사용량을 기록해 CI 비용 추적 |
| 조직 관리 콘솔 | 팀·사용자별 사용량 모니터링 |

> 명령 이름과 표시 항목은 버전과 요금제에 따라 다를 수 있으므로 교육 전에 확인하세요.

## 3. 최적화 방법

### 3-1. 세션 관리

| 방법 | 설명 | EduHub 예시 |
|---|---|---|
| **작업마다 `/clear`** | 관련 없는 이전 대화를 비운다 | N+1 수정이 끝나면 `/clear` 후 MFE 테마 작업 시작 |
| **직접 `/compact`** | 자동 압축 전에, 남길 내용을 지정해 요약 | `/compact 수강 취소 API 설계 결정과 남은 TODO만 남겨줘` |
| **긴 작업은 나누기** | 한 세션에 모든 걸 몰아넣지 않는다 | "백엔드 구현" 세션과 "프론트 연결" 세션 분리 |
| **진행 상황을 파일로** | 세션을 바꿔도 이어갈 수 있도록 | `docs/progress/42-cancel.md`에 결정 사항 기록 |

### 3-2. 고정 비용 줄이기 (매 턴 들어가는 것)

| 방법 | 설명 |
|---|---|
| **CLAUDE.md 다이어트** | 매 턴 포함된다. 핵심 규칙만 남기고 상세 내용은 스킬로 이동 ([CLAUDE.md 예제](./02-claude-md.md)) |
| **하위 디렉터리 CLAUDE.md** | 백엔드 규칙은 `backend/CLAUDE.md`로 → 프론트 작업 때는 읽히지 않음 |
| **스킬 활용** | 평소에는 설명만, 필요할 때만 본문 로딩 ([사내 프레임워크 예제](./07-custom-framework.md)) |
| **안 쓰는 MCP 서버 끄기** | 연결된 서버의 도구 정의가 컨텍스트를 차지한다. 프로젝트에 필요한 서버만 연결 |

### 3-3. 도구 결과 줄이기 (가장 효과가 큼)

| 방법 | ❌ 낭비 | ✅ 절약 |
|---|---|---|
| **정확한 위치 알려주기** | "수강 신청 관련 코드 찾아서 고쳐줘" | "`enrollment/EnrollmentService.java`의 `enroll()` 수정해줘" |
| **명령 출력 줄이기** | `./gradlew test` (수천 줄 로그) | `./gradlew test -q`, 실패 시 마지막 부분만 확인하도록 CLAUDE.md에 명시 |
| **큰 파일·생성물 제외** | `node_modules/`, `build/`, `generated/` 탐색 | 권한 설정에서 읽기 차단, CLAUDE.md에 "생성 코드는 읽지 않는다" |
| **로그는 필요한 부분만** | 서버 로그 전체 붙여넣기 | 스택 트레이스와 관련 요청 부분만 |
| **탐색은 서브에이전트에게** | 메인 대화에서 파일 50개를 읽음 | 서브에이전트가 별도 컨텍스트에서 탐색하고 **요약만** 반환 |

```json
// .claude/settings.json (일부): 읽을 필요 없는 대용량 경로 차단
{
  "permissions": {
    "deny": [
      "Read(./frontend/node_modules/**)",
      "Read(./frontend/apps/*/dist/**)",
      "Read(./backend/build/**)",
      "Read(./frontend/packages/api-client/src/generated/**)"
    ]
  }
}
```

> 생성된 API 클라이언트를 차단하면 Claude가 타입 정의를 볼 수 없습니다. 대신 `/v3/api-docs` 스펙이나 Swagger를 보도록 안내하는 등, 차단할 때는 **대체 경로**를 함께 정합니다.

### 3-4. 재작업 줄이기

| 방법 | 설명 |
|---|---|
| **Plan 모드로 먼저 합의** | 잘못된 방향으로 구현 후 되돌리는 것이 가장 큰 낭비 |
| **완료 기준 명시** | "테스트 통과", "Swagger에 표시" 등 기준이 있으면 불필요한 반복이 줄어든다 |
| **잘못 가면 일찍 멈추기** | 방향이 틀리면 바로 중단(Esc)하고 지시를 고친다 |

### 3-5. 모델 선택

| 작업 | 추천 |
|---|---|
| 설계, 복잡한 버그, 대규모 리팩터링 | 가장 성능이 높은 모델 |
| 일상적인 구현, 테스트 작성 | 균형형 모델 |
| 단순 반복 작업, 대량 자동화(CI), 서브에이전트의 탐색 | 빠르고 저렴한 모델 |

- 서브에이전트는 정의 파일에서 모델을 따로 지정할 수 있다 (예: 탐색 전용은 저렴한 모델)

### 3-6. 자동화(CI)에서의 비용 관리

- PR마다 전체 저장소가 아닌 **변경된 파일 중심**으로 리뷰하도록 프롬프트 작성
- 최대 턴 수 제한 등으로 무한 반복 방지
- 실행 결과의 사용량을 기록하고 월별 추이 확인

## 4. 실습: 같은 과제, 다른 사용량

**과제:** "과정 목록 API의 N+1 문제 수정" (문제 P1)

| 실험 | 방법 | 기록할 것 |
|---|---|---|
| A | 긴 대화를 이어온 세션에서 "N+1 고쳐줘" | `/context`, 사용량, 결과 품질 |
| B | `/clear` 후 파일 위치와 완료 기준을 명시해 지시 | 같은 항목 |
| C | B + 탐색은 서브에이전트, 테스트 출력은 `-q` | 같은 항목 |

결과를 비교하는 차트를 아티팩트로 만들어 팀에 공유합니다.

## 5. 요약: 토큰 최적화 체크리스트

- [ ] 작업이 바뀌면 `/clear`
- [ ] CLAUDE.md는 짧게, 상세 내용은 스킬로
- [ ] 쓰지 않는 MCP 서버는 연결 해제
- [ ] 파일 위치와 완료 기준을 구체적으로 지시
- [ ] 큰 출력은 줄이고, 생성물·의존성 폴더는 읽기 차단
- [ ] 넓은 탐색은 서브에이전트에게
- [ ] 큰 작업은 Plan 모드로 먼저 합의
- [ ] 작업 난이도에 맞는 모델 선택
