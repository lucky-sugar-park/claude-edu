## 2. 터미널(CLI) vs 데스크톱 앱

| 구분 | 터미널(CLI) | 데스크톱 앱 |
|---|---|---|
| **진입 장벽** | 터미널 사용에 익숙해야 함 | 일반 앱처럼 설치·실행, 터미널 지식 불필요 |
| **변경 내용 검토** | 텍스트 diff | 시각적 diff 화면 |
| **병렬 작업** | 터미널 창을 여러 개 띄워 관리 | 한 창에서 여러 세션, 워크트리 자동 관리 |
| **자동화** | 스크립트, 파이프, CI, cron 연동에 강함 | 앱 안의 예약 작업 기능 위주 |
| **부가 기능** | 원격 제어 등 CLI 전용 명령 | 앱 미리보기, 파일 첨부, 휴대폰에서 작업 지시 |
| **실행 환경** | Linux 서버 등 어디서나 | Mac, Windows |

### 이런 사람에게 추천

| 터미널(CLI) | 데스크톱 앱 |
|---|---|
| 터미널과 Git 명령에 익숙한 개발자 | 터미널이 낯선 입문자, 기획자·디자이너 |
| 서버에 SSH로 접속해 작업하는 경우 | 변경 내용을 화면으로 꼼꼼히 보고 싶은 경우 |
| 스크립트·CI로 자동화하려는 경우 | 여러 작업을 한 화면에서 관리하고 싶은 경우 |
| 새 기능을 가장 먼저 쓰고 싶은 경우 | 설치와 설정을 간단히 끝내고 싶은 경우 |

> 💡 둘 중 하나만 고를 필요는 없습니다. 같은 프로젝트의 CLAUDE.md, 스킬, 설정이 두 환경에 똑같이 적용되므로, **평소에는 데스크톱 앱, 자동화와 서버 작업은 터미널**처럼 섞어 써도 됩니다.

## 3. 전체 환경 장단점

### 터미널(CLI)

| 장점 | 단점 |
|---|---|
| 모든 기능 사용 가능, 새 기능이 가장 먼저 나옴 | 터미널 사용법을 알아야 함 |
| 파이프(`\|`), 스크립트, CI, cron과 연동 | diff가 텍스트라 큰 변경은 검토가 불편 |
| 서버(SSH), 컨테이너 등 어디서나 실행 | 여러 작업을 하려면 창·탭을 직접 관리 |
| 가볍고 빠름 | 이미지 첨부 등 일부 동작은 단축키를 알아야 함 |

### IDE 확장 (VS Code, JetBrains)

| 장점 | 단점 |
|---|---|
| 열린 파일·선택한 코드가 바로 맥락으로 전달 | IDE를 켜야 사용 가능 |
| 변경 내용을 IDE의 diff 화면으로 확인·수락 | IDE마다 지원 기능 차이가 있을 수 있음 |
| 코드 작성 흐름을 끊지 않음 | 자동화 용도로는 부적합 |

### 데스크톱 앱

| 장점 | 단점 |
|---|---|
| 설치가 쉽고 터미널 지식 불필요 | Mac, Windows에서만 사용 |
| 시각적 diff, 앱 미리보기, 파일 첨부 | 파이프·스크립트 연동은 CLI보다 약함 |
| 여러 세션과 워크트리를 한 화면에서 관리 | 일부 고급 명령은 CLI에서 먼저 지원 |
| 로컬 세션과 클라우드 세션을 함께 관리 | |

### 클라우드(웹)

| 장점 | 단점 |
|---|---|
| 설치 불필요, 브라우저만 있으면 됨 | GitHub 저장소가 필요 |
| 내 컴퓨터를 꺼도 작업 계속 진행 | 로컬 파일, 로컬 DB, 사내망 접근 불가 (네트워크 정책에 따라 제한) |
| 여러 작업을 동시에 맡기기 쉬움 | 세션이 끝나면 컨테이너가 정리됨 → **커밋·푸시 필수** |
| 격리된 환경이라 내 컴퓨터에 영향 없음 | 의존성 설치 등 환경 설정(설정 스크립트)이 필요 |

### 모바일

| 장점 | 단점 |
|---|---|
| 이동 중, 회의 중에도 작업 지시·확인 | 긴 코드 읽기와 편집이 불편 |
| 질문에 답하거나 승인만 빠르게 처리 | 실제 작업은 클라우드나 내 컴퓨터에서 실행됨 |
| 작업 완료 알림 확인 | 복잡한 지시를 입력하기 불편 |

### 한눈에 비교

| 기준 | 터미널 | IDE | 데스크톱 | 클라우드 | 모바일 |
|---|---|---|---|---|---|
| 배우기 쉬움 | △ | ○ | ◎ | ◎ | ◎ |
| 코드 검토 | △ | ◎ | ◎ | ○ | △ |
| 로컬 자원 접근 | ◎ | ◎ | ◎ | ✕ | (원격 조작 시 ○) |

| 자동화 | ◎ | ✕ | △ | ○ | ✕ |
| 장소 제약 없음 | △ | △ | △ | ◎ | ◎ |

## 4. 터미널 도구: 윈도우 중심 + wmux, tmux

### 4-1. 윈도우에서 실행하는 두 가지 방식

| 방식 | 설명 | 추천 대상 |
|---|---|---|
| **윈도우 네이티브** | PowerShell 등에서 바로 실행. Git for Windows(Git Bash) 설치 권장 | 윈도우용 도구(.NET, Windows 전용 빌드)를 쓰는 프로젝트 |
| **WSL2 (Linux)** | 윈도우 안의 Linux(Ubuntu 등)에서 실행 | Java/Node 웹 개발, 서버가 Linux인 프로젝트, Linux 명령에 익숙한 경우 |

**설치 예시** (공식 문서의 최신 방법을 우선 확인하세요)

```powershell
# PowerShell (네이티브 설치 스크립트)
irm https://claude.ai/install.ps1 | iex

# 또는 Node.js가 설치되어 있다면
npm install -g @anthropic-ai/claude-code
```

```bash
# WSL(Ubuntu) 안에서
curl -fsSL https://claude.ai/install.sh | bash
```

> 💡 EduHub처럼 Java + Node 기반 프로젝트는 **WSL2**에서 쓰면 셸 스크립트, 훅(bash), Docker 연동이 수월합니다. 이때 프로젝트 파일도 WSL 파일 시스템(`~/projects/...`)에 두면 속도가 빠릅니다.

### 4-2. 많이 쓰는 윈도우 터미널 도구

| 도구 | 특징 | 추천 용도 |
|---|---|---|
| **Windows Terminal** | Microsoft 공식 터미널. 탭, 화면 분할, PowerShell·WSL·Git Bash를 한 곳에서 | **가장 추천**. 기본 터미널로 사용 |
| **PowerShell 7** | 최신 PowerShell. Windows Terminal 안에서 실행 | 윈도우 네이티브 방식 |
| **WSL2 (Ubuntu)** | Linux 셸 환경 | 웹·서버 개발 |
| **Git Bash** | Git for Windows에 포함된 bash | 가볍게 bash 명령이 필요할 때 |
| **VS Code 통합 터미널** | 편집기 안의 터미널 (PowerShell, WSL, Git Bash 선택 가능) | 편집하면서 CLI 사용, IDE 확장과 함께 |
| **wmux** | AI 코딩 에이전트를 여러 개 나란히 돌리기 위한 윈도우 네이티브 멀티플렉서 앱 (커뮤니티 오픈소스) | Claude Code 세션 여러 개를 병렬로 운영 |
| **tmux** (WSL·Linux·Mac) | 대표적인 터미널 멀티플렉서. 세션 유지, 화면 분할 | 서버 작업, SSH 끊김 대비, WSL 사용자 |

### 4-3. Windows Terminal 간단 사용법

**설치**

```powershell
winget install Microsoft.WindowsTerminal
```

Windows 11에는 기본 설치되어 있습니다. Microsoft Store에서도 설치할 수 있습니다.

**자주 쓰는 단축키** (기본값 기준)

| 동작 | 단축키 |
|---|---|
| 새 탭 | `Ctrl + Shift + T` |
| 특정 프로필로 새 탭 (드롭다운) | `Ctrl + Shift + 숫자` |
| 화면 세로 분할 | `Alt + Shift + +` |
| 화면 가로 분할 | `Alt + Shift + -` |
| 분할 창 이동 | `Alt + 방향키` |
| 창·탭 닫기 | `Ctrl + Shift + W` |
| 복사 / 붙여넣기 | `Ctrl + Shift + C` / `Ctrl + Shift + V` (텍스트 선택 시 `Ctrl + C`도 가능) |
| 설정 열기 | `Ctrl + ,` |
| 명령 팔레트 | `Ctrl + Shift + P` |

**Claude Code용 추천 설정**

1. **기본 프로필 지정**: 설정 → 시작 → 기본 프로필을 `Ubuntu`(WSL) 또는 `PowerShell`로
2. **시작 디렉터리**: 프로필 설정에서 프로젝트 폴더로 지정하면 바로 `claude` 실행 가능
3. **글꼴**: 한글과 기호가 잘 보이는 고정폭 글꼴(예: D2Coding, Cascadia Code) 사용
4. **화면 분할 활용 예시**

```
┌──────────────────────────┬─────────────────────┐
│                          │ 백엔드 서버 실행      │
│  claude (작업 지시)       │ ./gradlew bootRun   │
│                          ├─────────────────────┤
│                          │ 프론트 개발 서버      │
│                          │ npm run dev         │
└──────────────────────────┴─────────────────────┘
```

5. **워크트리 병렬 작업**: 탭마다 다른 워크트리 폴더에서 `claude`를 실행 ([예제](./01-basics-and-workflow.md#모듈-7-git--협업-워크플로우))

### 4-4. 터미널에서 Claude Code 기본 조작

| 동작 | 방법 |
|---|---|
| 시작 | 프로젝트 폴더에서 `claude` |
| 이전 대화 이어서 | `claude --continue` 또는 `claude --resume` |
| 한 번만 실행하고 결과 출력 | `claude -p "질문"` |
| 작업 중단 | `Esc` |
| 이전 시점으로 되돌리기 | `Esc` 두 번 (체크포인트 목록) |
| 권한 모드 전환 (Plan 모드 포함) | `Shift + Tab` |
| 여러 줄 입력 | 줄 끝에 `\` 입력 후 Enter (터미널에 따라 `Shift + Enter` 설정 가능, `/terminal-setup` 참고) |
| 이미지 붙여넣기 | 이미지 파일 경로를 입력하거나 드래그 (클립보드 붙여넣기 단축키는 환경에 따라 다름) |
| 도움말 | `/help` |

> 단축키는 운영체제, 터미널, 버전에 따라 다를 수 있습니다. `/help`와 공식 문서로 확인하세요.

### 4-5. wmux: 윈도우용 AI 에이전트 멀티플렉서

**무엇인가:** Claude Code 같은 CLI 에이전트를 **여러 개 나란히** 실행하고 관리하기 위한 데스크톱 앱입니다. WSL 없이 윈도우에서 바로 동작하며(macOS도 지원), MIT 라이선스의 커뮤니티 오픈소스입니다. ([openwong2kim/wmux](https://github.com/openwong2kim/wmux))

> ⚠️ "wmux"라는 이름의 **서로 다른 프로젝트가 여러 개** 있습니다. 설치 전에 저장소를 확인하세요. 공식 Anthropic 도구가 아니며, 설치 파일 서명 여부 등 사내 보안 정책에 맞는지 먼저 검토합니다. 아래 내용은 2026년 10월 기준입니다.

**주요 기능**

| 기능 | 설명 |
|---|---|
| 에이전트별 화면 분할 | 에이전트 하나당 창 하나, 여러 에이전트를 한 화면에서 |
| 세션 유지 | 백그라운드 데몬이 세션을 유지해 앱을 닫거나 재부팅해도 이어서 작업 |
| git worktree 분배 | 프롬프트 하나로 여러 작업을 각자의 워크트리·브랜치에서 실행하고 diff 검토 |
| 전체 에이전트 목록(Fleet) | 모든 에이전트를 한 목록으로, 입력이 필요한 에이전트를 위로 |
| 브라우저 제어 | MCP 도구로 내장 브라우저나 Chrome 조작 |
| 모바일 연동 | iOS 앱에서 에이전트 질문에 답하기 |

**설치**

```powershell
winget install openwong2kim.wmux
# 또는
choco install wmux
```

**기본 단축키**

| 동작 | 단축키 |
|---|---|
| 오른쪽으로 분할 | `Ctrl + D` |
| 아래로 분할 | `Ctrl + Shift + D` |
| 새 워크스페이스 | `Ctrl + N` |
| 워크스페이스 1~8로 이동 | `Ctrl + 1` ~ `Ctrl + 8` |
| 새 탭 / 탭 닫기 | `Ctrl + T` / `Ctrl + W` |
| 전체 에이전트 목록 | `Ctrl + Shift + A` |
| 명령 팔레트 | `Ctrl + K` |
| 설정 | `Ctrl + ,` |

**EduHub 활용 예:** 워크스페이스 하나에 "백엔드 N+1 수정", "MFE 테마 수정", "테스트 보강" 에이전트를 나란히 띄우고, 입력이 필요한 에이전트만 골라 응답합니다.

### 4-6. tmux: 리눅스(WSL, Mac)용 터미널 멀티플렉서

**무엇인가:** 터미널 하나 안에서 **여러 창과 분할 화면**을 만들고, 터미널을 닫거나 SSH 연결이 끊겨도 **세션이 계속 살아 있게** 해 주는 도구입니다. 리눅스 서버, WSL, macOS에서 널리 쓰입니다.

**Claude Code와 함께 쓰면 좋은 이유**
- 서버에서 Claude Code에 긴 작업을 맡기고 SSH를 끊어도 작업이 계속된다
- `claude`, 백엔드 서버, 프론트 서버, 로그를 한 화면에 나눠 본다
- 워크트리별 Claude 세션을 창(window)으로 나눠 관리한다

**설치**

```bash
sudo apt install tmux      # Ubuntu, WSL
brew install tmux          # macOS
```

**세션 관리**

| 동작 | 명령 |
|---|---|
| 이름을 붙여 새 세션 시작 | `tmux new -s eduhub` |
| 세션 목록 | `tmux ls` |
| 세션에서 빠져나오기 (세션은 유지) | `Ctrl + b` 누른 뒤 `d` |
| 세션에 다시 접속 | `tmux attach -t eduhub` |
| 세션 종료 | `tmux kill-session -t eduhub` |

**기본 단축키** (모두 `Ctrl + b`를 먼저 누른 뒤 입력)

| 동작 | 키 |
|---|---|
| 좌우로 분할 | `%` |
| 위아래로 분할 | `"` |
| 분할 창 이동 | 방향키 |
| 현재 창 확대/복원 | `z` |
| 분할 창 닫기 | `x` |
| 새 창(window) | `c` |

| 창 번호로 이동 | `0` ~ `9` |
| 스크롤 모드 (위로 보기) | `[` (빠져나오기 `q`) |

**EduHub 작업 화면 만들기 예시**

```bash
tmux new -s eduhub -c ~/projects/eduhub     # 세션 시작
# Ctrl+b %  → 오른쪽 창에서: cd backend && ./gradlew bootRun
# Ctrl+b "  → 오른쪽 아래 창에서: cd frontend && npm run dev
# Ctrl+b ←  → 왼쪽 창에서: claude
# Ctrl+b c  → 새 창에서 다른 워크트리의 claude 실행
```

**tmux 사용 시 참고**
- 일부 단축키(예: `Shift + Enter` 줄바꿈)가 tmux 안에서 다르게 동작할 수 있다. 이 경우 `\` + Enter로 여러 줄 입력
- 마우스 스크롤·선택을 쓰려면 `~/.tmux.conf`에 `set -g mouse on` 추가

### 4-8. 윈도우에서 자주 겪는 문제

| 문제 | 해결 |
|---|---|
| 한글이 깨짐 | Windows Terminal + UTF-8 글꼴 사용, PowerShell 7 사용 |
| WSL에서 윈도우 폴더(`/mnt/c/...`) 작업이 느림 | 프로젝트를 WSL 파일 시스템으로 옮기기 |

| `gradlew` 실행 권한 문제 (WSL) | `chmod +x gradlew` |
