# 개념 정리: 프로젝트, 디렉터리, 세션 — 그리고 잘 활용하는 방법

> 관련 모듈: 8 (3, 7, 19와 연결)
> 예제 프로젝트: [EduHub](./00-sample-project.md)

> ⚠️ 명령 옵션과 저장 위치는 버전에 따라 바뀔 수 있습니다. 교육 전에 `claude --help`와 공식 문서로 확인하세요.

---

## 1. 세 가지 개념 한눈에 보기

| 개념 | 한 줄 정의 | 결정하는 것 |
|---|---|---|
| **작업 디렉터리** | `claude`를 실행한 폴더 | Claude가 기본으로 **읽고 수정할 수 있는 범위**, 어떤 설정을 불러올지 |
| **프로젝트** | 작업 디렉터리(보통 Git 저장소 루트)를 기준으로 묶이는 설정과 기록의 단위 | CLAUDE.md, `.claude/` 설정, 스킬, 에이전트, MCP, **세션 기록** |
| **세션** | 하나의 대화. 시작부터 끝까지 이어지는 컨텍스트 | Claude가 **지금 기억하는 내용**(대화, 읽은 파일, 도구 결과) |

```
사용자 범위 (~/.claude/)               ← 내 모든 프로젝트에 적용
 │   CLAUDE.md, settings.json, skills/, agents/
 │
 └── 프로젝트 = 작업 디렉터리 (예: ~/projects/eduhub)
      │   CLAUDE.md, .claude/settings.json, .claude/skills/, .claude/agents/, .mcp.json
      │
      ├── 세션 A: "N+1 문제 수정"          ← 대화 하나 = 컨텍스트 하나
      ├── 세션 B: "수강 취소 기능"
      └── 세션 C: "MFE 테마 수정"
```

> 💡 **헷갈리기 쉬운 점:** Claude 앱(claude.ai)의 **"프로젝트"** 기능(지식 파일과 지침을 모아 두는 공간)과 Claude Code의 프로젝트는 다른 개념입니다. Claude Code에서는 **"어느 폴더에서 실행했는가"**가 곧 프로젝트입니다.

## 2. 작업 디렉터리

### 2-1. 무엇이 정해지는가

- **접근 범위**: Claude는 기본적으로 작업 디렉터리와 그 하위 폴더에서 파일을 읽고 수정한다. 바깥 폴더는 추가로 허용해야 한다
- **불러오는 설정**: 그 폴더의 CLAUDE.md, `.claude/` 설정, `.mcp.json`
- **명령 실행 위치**: 테스트·빌드 명령이 이 위치를 기준으로 실행된다

### 2-2. 어디서 실행할까

| 실행 위치 | 장점 | 단점 | 추천 상황 |
|---|---|---|---|
| **저장소 루트** (`eduhub/`) | 백엔드·프론트를 함께 다룸, 공통 설정 적용 | 범위가 넓어 탐색 비용 증가 | 풀스택 기능, 대부분의 경우 (**기본 추천**) |
| **하위 폴더** (`eduhub/backend/`) | 범위가 좁아 빠르고 토큰 절약 | 프론트 연동 작업 불가, 루트 설정이 적용되는지 확인 필요 | 백엔드만 집중하는 작업 |
| **홈 디렉터리** (`~`) | — | 범위가 너무 넓고, 관련 없는 파일 접근 위험 | **피한다** |

### 2-3. 다른 폴더를 함께 다뤄야 할 때

백엔드와 프론트가 **서로 다른 저장소**인 경우:

```bash
# 백엔드 저장소에서 실행하면서 프론트 저장소도 접근 허용
cd ~/projects/eduhub-backend
claude --add-dir ../eduhub-frontend
```

대화 중에는 `/add-dir`로 추가할 수 있습니다. 자주 함께 다룬다면 두 저장소를 담는 상위 작업 폴더를 만들고 거기에 공통 CLAUDE.md를 두는 방법도 있습니다.

## 3. 프로젝트

### 3-1. 프로젝트 단위로 관리되는 것

| 항목 | 위치 | Git 공유 |
|---|---|---|
| 프로젝트 지침 | `CLAUDE.md`, 하위 폴더의 `CLAUDE.md` | ○ |
| 팀 설정 (권한, 훅) | `.claude/settings.json` | ○ |
| 개인 설정 | `.claude/settings.local.json` | ✕ (`.gitignore`) |
| 스킬, 에이전트, 커맨드 | `.claude/skills/`, `.claude/agents/`, `.claude/commands/` | ○ |
| MCP 서버 | `.mcp.json` | ○ |
| 세션 기록 | 사용자 폴더(`~/.claude/` 아래)에 프로젝트 경로별로 저장 | ✕ |

### 3-2. 설정 적용 순서 (범위)

```
조직 관리 정책  >  프로젝트 개인(local)  >  프로젝트 공유  >  사용자
(가장 우선)                                              (가장 넓은 범위)
```

- 팀이 함께 지킬 것 → **프로젝트 공유** (`.claude/settings.json`, 커밋)
- 나만의 선호·실험 → **프로젝트 개인** (`.claude/settings.local.json`) 또는 **사용자** (`~/.claude/`)
- 회사 전체 규정 → **조직 관리 정책**

### 3-3. 모노레포 vs 멀티 저장소

| 구조 | 추천 구성 |
|---|---|
| **모노레포** (EduHub처럼 `backend/` + `frontend/`) | 루트에서 실행. 루트 CLAUDE.md에는 공통 규칙, `backend/CLAUDE.md`·`frontend/CLAUDE.md`에 영역별 규칙 ([예제](./02-claude-md.md)) |
| **멀티 저장소** (백엔드·프론트 분리) | 주로 작업하는 저장소에서 실행 + `--add-dir`. 각 저장소에 자체 CLAUDE.md. 공통 규칙은 플러그인이나 사용자 범위로 |
| **마이크로프론트엔드가 저장소별로 분리** | remote 하나만 고칠 때는 해당 저장소에서, shell 연동 작업은 shell 저장소에서 실행 + 관련 remote를 `--add-dir` |

## 4. 세션

### 4-1. 세션이란

- `claude`를 실행하면 **새 세션**이 시작된다
- 세션 안의 모든 대화, 읽은 파일, 명령 결과가 **컨텍스트**에 쌓인다 ([모듈 1](../CURRICULUM.md), [토큰 최적화](./08-token-optimization.md))
- 세션은 **작업 디렉터리별로 기록**되어, 같은 폴더에서 이어서 열 수 있다
- 세션 안에서는 **체크포인트**로 이전 시점으로 되돌릴 수 있다

### 4-2. 세션 다루기

| 하고 싶은 것 | 방법 |
|---|---|
| 새 세션 시작 | `claude` |
| 이 폴더의 가장 최근 세션 이어가기 | `claude --continue` (`-c`) |
| 이전 세션 목록에서 골라 이어가기 | `claude --resume` (`-r`), 대화 중에는 `/resume` |
| 같은 세션에서 컨텍스트만 비우기 | `/clear` |
| 컨텍스트를 요약해 공간 확보 | `/compact [남길 내용]` |
| 현재 컨텍스트 사용량 보기 | `/context` |
| 헤드리스에서 이전 세션 이어가기 | `claude -p --resume <세션 ID> "다음 지시"` |

### 4-3. 새 세션 vs 이어가기 판단 기준

| 상황 | 선택 |
|---|---|
| 어제 하던 작업을 계속 | `--continue` / `--resume` |
| 작업 주제가 바뀜 | 새 세션 또는 `/clear` |
| 같은 실수가 반복되고 대화가 꼬임 | 새 세션 + 더 나은 지시 |
| 컨텍스트가 거의 찼지만 같은 작업 | `/compact`로 요약 후 계속 |
| 며칠에 걸친 큰 작업 | 진행 상황을 **파일로 남기고** 세션은 단계별로 새로 |

### 4-4. 세션 사이에 맥락 넘기기

세션이 바뀌면 이전 대화를 기억하지 못합니다. 오래 이어지는 작업은 **파일을 기억 장치로** 씁니다.

```markdown
<!-- docs/progress/42-cancel-enrollment.md -->
# 수강 취소 기능 (#42) 진행 상황

## 결정 사항
- 취소 기한: 교육 시작 3일 전 (기획 확정)
- 대기자 승격은 같은 트랜잭션에서 처리 (이벤트 분리는 다음 단계)

## 완료
- [x] DELETE /api/v1/enrollments/{id}
- [x] 서비스 테스트 6개

## 남은 일
- [ ] 프론트 취소 버튼, 확인 Dialog
- [ ] 동시 취소 테스트
```

```text
docs/progress/42-cancel-enrollment.md를 읽고 남은 일부터 이어서 진행해줘. 끝나면 이 파일을 갱신해줘.
```

## 5. 세 개념을 함께 활용하기

### 5-1. 병렬 작업: 디렉터리를 나누면 세션도 나뉜다

같은 폴더에서 세션 두 개가 동시에 파일을 고치면 충돌합니다. **git worktree로 디렉터리를 나누면** 각자 독립된 작업 공간과 세션 기록을 가집니다.

```bash
git worktree add ../eduhub-42-cancel   -b feature/42-cancel-enrollment
git worktree add ../eduhub-57-nplus1   -b fix/57-n-plus-one

cd ../eduhub-42-cancel && claude    # 세션 1
cd ../eduhub-57-nplus1 && claude    # 세션 2 (다른 터미널, tmux 창 등)
```

| 구성 | 효과 |
|---|---|
| 작업 1개 = 브랜치 1개 = 워크트리(디렉터리) 1개 = 세션 1개 | 충돌 없음, 맥락이 섞이지 않음, 정리하기 쉬움 |

데스크톱 앱이나 wmux처럼 워크트리를 자동으로 관리해 주는 도구를 쓰면 더 간단합니다 ([환경 비교](./14-environments-and-terminals.md)).

### 5-2. 클라우드 세션

- 클라우드(웹) 세션은 **세션마다 새 컨테이너**에 저장소를 클론해 시작한다 → 세션 = 독립된 작업 공간
- 세션이 끝나면 컨테이너가 정리되므로 결과는 **브랜치에 커밋·푸시**해야 남는다
- 하나의 클라우드 세션은 보통 하나의 브랜치로 결과를 낸다 → "작업 1개 = 세션 1개 = 브랜치 1개" 원칙과 잘 맞는다

### 5-3. 서브에이전트와 세션

- 서브에이전트는 메인 세션 안에서 **별도 컨텍스트**를 가지고 일한 뒤 요약만 돌려준다 ([에이전트](./10-agents.md))
- 새 세션을 여는 대신 서브에이전트에 탐색을 맡기면, 메인 세션의 맥락을 유지하면서 컨텍스트를 아낄 수 있다

## 6. 모범 사례 요약

| 영역 | 모범 사례 |
|---|---|
| **디렉터리** | 저장소 루트에서 실행. 홈 디렉터리 같은 넓은 곳에서 실행하지 않기. 다른 저장소는 `--add-dir`로 필요한 것만 |
| **프로젝트** | 팀 규칙은 `.claude/settings.json`·CLAUDE.md로 커밋, 개인 설정은 `settings.local.json`(커밋 금지). 모노레포는 하위 CLAUDE.md로 영역 분리 |
| **세션** | 세션 하나에 작업 하나. 주제가 바뀌면 `/clear`나 새 세션. 이어갈 때는 `--continue`/`--resume` |
| **장기 작업** | 진행 상황·결정 사항을 파일로 남기고, 새 세션에서 그 파일부터 읽게 하기 |
| **병렬 작업** | 작업마다 브랜치 + 워크트리 + 세션을 하나씩 |
| **클라우드** | 세션이 끝나기 전에 커밋·푸시. 세션 하나에 브랜치 하나 |

## 7. 실습

1. EduHub 루트와 `backend/`에서 각각 `claude`를 실행하고 "이 프로젝트 구조를 설명해줘"를 지시 → 범위와 적용된 CLAUDE.md 차이 비교
2. 백엔드·프론트를 별도 폴더로 복사한 뒤 `--add-dir`로 두 폴더를 함께 다루며 "수강 취소 API와 화면 연결" 수행
3. 작업 도중 종료한 뒤 `claude --continue`로 이어가기, `claude --resume`으로 다른 세션 골라 열기
4. 진행 상황 파일을 만들고, `/clear` 후 새 컨텍스트에서 그 파일만으로 작업을 이어갈 수 있는지 확인
5. 워크트리 두 개를 만들고 각각 세션을 띄워 동시에 작업한 뒤 PR 두 개로 정리
